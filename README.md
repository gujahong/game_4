# 습작4

어둠 속을 등불 하나로 걷는 다크 판타지 픽셀아트 게임. Godot 4.7.1.

**이 게임의 문장 하나** — *등불이 비추는 것만 실재한다.* 보이는 것이 등불이 닿는 데까지다.
**다만 이건 상징이지 규칙이 아니다** — 안 비춘 것이 정말 없어지는 세계는 아니고, 결사 사람들이
새겨 두고 인용하는 옛말이다.

화면은 대체로 회색이다. 필터가 채도 낮은 것을 걷어내고 쨍한 것만 남기기 때문이고, 등불이
그중 제일 또렷하다. **다만 "색을 가진 것은 등불뿐"이 정해진 규칙은 아니다** — 스테인드글라스도
비석의 붉은 균열도 색이 남는다.

## 무슨 이야기인가

```
이 세상들은 어떤 초월적인 존재의 꿈이다.  그 존재가 깨어나려 하는 것이 "이상"이다.
주인공은 비밀 결사의 수호자로, 그 꿈으로 건너가 이상을 풀러 간다.
```

**그런데 건너가는 것 자체가 세상을 흔든다.** 다른 세상에서 흘러들어온 것이 섞이면 그 세계가
불안정해지고, 누군가는 *여기가 꿈이라는 것*을 깨닫는다. 깨달은 사람은 미쳐서 괴물이 된다.
**결사가 소방수이자 방화범이다.**

그리고 그것을 먼저 깨달은 단원 하나가, 결사를 줄이려고 세상을 넘나드는 단원들을 '사고'로
죽여 왔다. **주인공은 남은 마지막 하나다. 본인은 모른다** — 거점인 서고가 텅 빈 이유가 그것이다.

세계관과 첫 꿈은 `작업일지.md`와 `첫꿈.md`에 있다.

## 어디를 걸어 다니는가

```
관문        경구가 뜨고, 등불이 켜지고, 관문이 드러난다. 문 앞에서 위로 걸어 들어간다
  ↓
서고        아카식 레코드. 심연 위에 놓인 십자 통로 — 가운데 홀에서 네 방향으로 뻗는다
  ↓         **서가 넷을 다 읽어야** 북쪽 길이 열린다 (읽는 장치는 `Records.gd`)
그것        안쪽. 눈으로 뒤덮인 고리가 지키고 있다
  ↓         잡으면 포탈이 열린다
계단의 방    아직 없음. 마을이 될 곳 — 포탈 · 기름 · 기록물.
  ↓         **구슬 하나가 갈 수 있는 꿈 하나다**
꿈          아직 없음. 첫 꿈의 이야기와 구현 스펙은 `첫꿈.md`에 다 있다
```

## 켜기

```bash
"C:\Users\진로교육원\Desktop\Godot_v4.7.1-stable_win64.exe" --path . res://scenes/Opening.tscn
```

| 보고 싶은 것 | 여는 씬 |
|---|---|
| 처음부터 (경구 → 관문) | `scenes/Opening.tscn` |
| 서고 (십자 통로, 걸어다님) | `scenes/Room.tscn` |
| 조우 복도 → 전투 | `scenes/Encounter.tscn` |
| 전투 구도만 (25초 건너뜀) | `scenes/Encounter.tscn` 뒤에 `-- --battle` |
| 등불 밝기 확인 사진 | `scenes/Battle.tscn` 뒤에 `-- --capture` |

`Esc`로 끄고 `F11`로 전체화면. 화면은 **960x540**을 정수배로만 늘린다.

**다른 컴퓨터에서 pull 받았으면 먼저 이걸 돌린다.** `.godot/`은 저장소에 안 올라가서,
새로 생긴 `class_name`들을 엔진이 모른 채로 씬을 열면 통째로 깨진다.

```bash
Godot --headless --path . --import
```

### 등불이 마나다

전에는 밝기 하나가 체력이자 자원이었는데 **둘로 나눴다**(2026-08-21).

```
체력       맞을 때만 준다.            0이면 패배
등불 눈금   0~10. 매 턴 이만큼 마나가 나온다
           2턴마다 1씩 마른다.        0이면 주먹질만 된다 (패배는 아니다)
```

**하스스톤인데 거꾸로다** — 크리스탈이 늘어나는 게 아니라 줄어든다. 기름을 붓는 턴은 지금은
손해고 다음 턴부터 이득이라, 램프를 할지 지금 때릴지가 매 턴 판단이 된다. 그리고 **전투가
길어지면 반드시 진다** — 따로 타이머를 안 건다.

**눈금이 곧 화면 밝기라 UI를 하나 더 안 그린다.** 눈금 6이면 화면이 그만큼 밝다. 자세한
규칙과 비용표는 `전투.md`에 있다.

전투는 **씬을 갈아타지 않는다.** 조우 화면 위에 `BattleStage`가 얹히고, 서 있던 그것과 내가
좌우로 옮겨 앉는다 — 아무것도 사라지지 않으니 카메라만 돈 것으로 읽힌다.

서고도 같은 방식이다. **방의 모양이 `TilesetRoom._walkable()` 하나에 모여 있어서**, 거기만
고치면 타일도 이동 판정도 지도 도구도 한꺼번에 따라온다. 판정을 두 군데 적으면 반드시
어긋난다.

## 만드는 것들

그림도 소리도 **코드로 찍는다.** `tools/`의 스크립트는 전부 0원이고 몇 번이든 다시 돌릴 수 있다.

```bash
Godot --headless --path . --script res://tools/_sfx.gd          # 효과음 열여섯 개
Godot --headless --path . --script res://tools/_map.gd          # 서고 구조를 그림과 글자로
Godot --headless --path . --script res://tools/_desat.gd        # 타일셋 채도 낮추기
Godot --headless --path . --script res://tools/_probe_sfx.gd    # 소리가 실제로 담겼는지 잼
```

`_map.gd`가 특히 요긴하다. 게임 화면은 등불이 좁아 한 번에 조금밖에 안 보여서, **통로가
제대로 놓였는지는 위에서 내려다봐야 안다.** 밖에서 폰으로 확인하려고 `seogo_map.png`를
저장소에 올려둔다.

PixelLab로 뽑는 것(인물·적)은 **다섯 단계 통틀어 200생성**이 상한이다. 뽑기 전에 프롬프트와
비용을 확인받는다.

**뽑은 뒤에 고칠 수 있는 것은 뽑아서 고치지 않는다.** 채도가 그랬다 — 프롬프트로 조절하려
했으면 헛돈을 썼을 텐데, `_desat.gd`로 숫자 하나만 바꾸면 됐다.

## 그림 규칙

**놓일 크기 그대로 뽑는다.** 크게 뽑아 줄이거나 작게 뽑아 늘리지 않는다. 내부 해상도가
960x540이고 화면 전체를 정수배로만 확대하므로, 놓일 크기로 만들면 도트 하나가 화면 픽셀
정수 개에 딱 떨어진다. 크기가 안 맞으면 **확대/축소 대신 투명 여백을 자르거나 덧붙인다.**

같은 이유로 픽셀 글꼴은 네이티브 크기(16px)의 정수배로만 쓴다.
